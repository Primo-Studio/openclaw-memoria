# Journal 2026-08-28 — refonte de l'interface sur shadcn/ui (+ deux correctifs serveur)

> Demande de Néto (27/08 au soir, capture à l'appui) : « l'UX/UI est horrible, la navigation pas ouf […]
> shadcn ou autre élément de UX design ne serait pas négligeable », et un mélange clair/sombre visible
> (sélecteurs noirs, cartes sombres au texte illisible en thème clair).

## 1. Correctif immédiat (27/08, déjà en production)
Des règles récentes utilisaient des jetons CSS **jamais définis** (`--card`, `--surface`, `--muted`,
`--bg-input`, `--err`) et retombaient donc sur leurs couleurs de repli **sombres** en thème clair. Alias
ajoutés dans `styles.css` → le mélange clair/sombre a disparu sans attendre la refonte.

## 2. Refonte shadcn/ui — méthode
Fondation (1 agent) → 4 lanes d'écrans en parallèle (worktrees) → revue visuelle multi-agents sur
**64 captures** → 3 lots de corrections → passe transverse (socle + cohérence produit) → contrôle final
(3 relecteurs, avant/après). Chaque agent devait **ouvrir les captures et juger ce qu'il voyait**, jamais
le code seul.

**Fondation** : Tailwind v4 + shadcn/ui (24 composants), jetons `src/styles/tokens.css`, coquille
`src/app/Shell.tsx` (sidebar à icônes, rail repliable, tiroir mobile, barre supérieure titre + actions,
préférences en menu), primitives `src/components/ui.tsx` (PageHeader, SectionCard, StatCard, DataTable,
Spinner, ErrorBanner, EmptyState, ConfirmButton, CopyButton), `scripts/ui-preview.mjs` (aperçu avec
données de démo + captures clair/sombre × bureau/mobile), `packages/web/UI-GUIDE.md`.

**16 écrans migrés**, puis corrigés. Faits marquants :
- **2 P0** : sur mobile, les tableaux de Partage et Journal débordaient sans indice — 2 agents sur 3
  invisibles, tâche impossible. Corrigé à la racine : `DataTable` bascule en **fiches** sous 640 px.
- **Contrastes mesurés**, pas jugés à l'œil (script oklch→sRGB→WCAG) : jetons d'état puis bouton primaire.
- **Cibles tactiles** portées à 44 px, lignes entières cliquables.
- **Cohérence produit** : tutoiement partout, un seul « Actualiser », un seul sélecteur d'agent, renvois
  cliquables, un seul mot (« souvenir »), Mémoire = consulter / Maintenance = nettoyer.
- **Ancien CSS supprimé** : `styles.css` (1 406 lignes), `.legacy-screen`, `MIGRATED_SCREENS`.

**Contrôle final** : les 3 lots déclarés **livrables, 0 bloquant**, aucune régression du retrait du CSS.

## 3. Deux correctifs serveur (issus de la revue, non corrigeables côté web)
- **Révisions** : `GET /v1/admin/revisions` ne renvoyait que des identifiants — on demandait à l'utilisateur
  d'arbitrer une contradiction sans lui montrer les souvenirs. La proposition transporte désormais le
  **texte, la catégorie, la date et l'état** des deux faits ; l'écran ne « pêche » plus dans les 200 derniers.
- **Libellés de thèmes** : « Le Memoria CLI », « Prefere Appelle Neto », « Part Tarif Horaire ».
  `cleanTopicLabel()` (`packages/core/src/cognition/topics.ts:250`, exporté) retire l'article de tête et
  applique une casse de phrase **arbitrée par le texte du fait** (un mot n'est démajusculé que s'il apparaît
  en minuscules dans le souvenir : « Hélène Rey » reste intact, « Gestion **des permissions** Postgres » est
  corrigé), préserve sigles et particules. Le bouton « Affiner les libellés (IA) » ne réintroduit plus le
  Title Case (il portait le prompt fautif : un clic aurait re-cassé ce qu'on venait de corriger).

### ⚠️ Note pour un futur `memoria retitle-topics` (mesuré, pas supposé)
Nettoyer la CHAÎNE existante ne rattrape que 2 défauts sur 4 :
`cleanTopicLabel('Le Memoria CLI')` → `Memoria CLI` ✅ · `('Part Tarif Horaire')` → `Part tarif horaire`
(le mot-outil « Part » reste) · `('Nouveau Boitier')` → inchangé, **l'accent détruit à la création ne peut
pas être inventé**. La commande devra donc **REGÉNÉRER depuis les faits du thème** :
`cleanTopicLabel(topicKeywordSurfaces(<faits>).slice(0,2).join(' '), { source: <faits> })` → `Nouveau boîtier`.
Boîte à outils : `cleanTopicLabel` (topics.ts:250), `topicSlug` (:723), `topicKeywordSurfaces` (:142),
boucle de référence `Memoria.refineTopicLabels` (memoria.ts:3285). ⚠️ `auto_themes_ai` est à `false` en
production : **aucun libellé existant ne change sans un clic**.

## 4. Pièges rencontrés (à retenir)
- **Clés i18n en double après une fusion par union** → le build Vite échoue sur « Duplicate key ».
  Toujours dédoublonner après une union de catalogues (arrivé deux fois).
- Deux agents coupés par la limite d'usage **après avoir écrit le code, avant le commit** : le travail était
  intact dans le worktree. Vérifier `git status` d'un worktree avant de relancer quoi que ce soit.
- Une capture Chrome headless prend ~60 s à rendre la main (Chrome 151) : le script passe par le protocole
  DevTools, et macOS impose ~500 px de largeur minimale de fenêtre (émulation d'appareil pour le vrai 390 px).
