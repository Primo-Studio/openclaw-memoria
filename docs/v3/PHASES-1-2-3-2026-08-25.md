## Phase 2 — Capture auto Claude Code + Codex ✅ (mécanisme validé, service planifié)

Claude Code + Codex sont des **MCP** (pas d'adaptateur à hooks comme OpenClaw) → la voie automatique
robuste = **Memoria récupère les conversations toute seule**, sur planning.

Livré :
- **`scripts/auto-import.sh`** : découvre les instances claude-code + codex via l'API locale, puis lance
  `memoria import --instance <id> --transcripts` pour chacune. Idempotent (seules les nouvelles fenêtres
  sont analysées). Log dans `~/.memoria/auto-import.log`. Accepte `--max-windows N` en 1er arg (test/coût).
- **`scripts/fr.primo-studio.memoria.autoimport.plist`** : service **launchd** copié dans
  `~/Library/LaunchAgents/`, **chargé** (`launchctl bootstrap`). `StartInterval = 21600` (**toutes les 6 h**),
  `RunAtLoad = false` (pas d'import coûteux au chargement).
- **Test réel** : `auto-import.sh 1` a lancé un import → **1355 fichiers** de transcripts Claude Code
  analysés, souvenirs extraits (gpt-4o-mini) qui arrivent **DORMANTS** dans l'écran **Revue** ✅. Mécanisme
  confirmé de bout en bout.

⚠️ **Coût & comportement à connaître** :
- L'import **ré-analyse les conversations avec le modèle** (gpt-4o-mini, peu cher mais **coût OpenAI réel**).
  Le 1er passage = **rattrapage complet** de l'historique (le plus gros) ; ensuite **incrémental** (seulement
  le nouveau) → coût faible en régime.
- Les souvenirs importés arrivent **en Revue** (à valider), pour éviter le bruit — ils ne sont pas actifs tant
  qu'on ne les approuve pas.
- **Arrêter / changer le rythme** : `launchctl bootout gui/$(id -u)/fr.primo-studio.memoria.autoimport`
  pour stopper ; éditer `StartInterval` dans le `.plist` puis recharger pour changer la fréquence.
- **ChatGPT** : couvert **s'il passe par OpenClaw** (adaptateur, déjà branché sur Koda) ou **Codex** (import
  ci-dessus). L'app/site **ChatGPT** standalone reste **hors de portée** (aucun accès local aux conversations).

## Phase 3 — Distribution (npm + signature) ✅ PRÉPARÉE (publication/notarisation = ton feu vert)

Publier sur npm (public, quasi irréversible) et notariser (soumission Apple) engagent tes identifiants →
**je prépare tout jusqu'au « une commande et c'est parti » + dry-run, mais je ne déclenche PAS l'envoi réel.**

### npm — prêt à publier
- Packages durcis (`packages/{core,daemon,mcp,cli}/package.json`) : ajout `files:["dist"]` (tarball propre),
  `publishConfig:{access:"public"}`, `license`, `repository`. **Dry-run OK** : `npm pack --dry-run` ne met que
  `dist/` dans le tarball.
- `web` = `private:true` (jamais publié). `adapter-openclaw` = `memoria-plugin` v4.0.0 déjà publiable.
- **🔴 DÉCISION À PRENDRE (bloquant)** : les packages s'appellent **`@memoria/*`** — ce scope npm ne t'appartient
  probablement pas (déjà pris). Il faut choisir un scope **que tu contrôles** : soit créer l'org npm
  **`@primo-studio`** (puis renommer `@memoria/*` → `@primo-studio/memoria-*` **partout**, y compris les
  dépendances internes croisées), soit des noms non scopés libres. Renommer touche tous les `import` internes →
  à faire d'un bloc, avec build+tests derrière.
- **Étapes de publication** (une fois le scope décidé) : `npm login` (ou token `NPM_TOKEN`) →
  `npm run build` → `npm publish --workspace @<scope>/core` (puis daemon, mcp, cli dans cet ordre de dépendance).
  Après publication : repasser les invocations locales `node ~/openclaw-memoria/...` en `npx -y @<scope>/mcp`.

### App macOS — signature prête
- ✅ **Certificat présent** : « Developer ID Application: Primo Studio (4QB44XVHNL) ».
- ✅ **Config Tauri** : ajout de `"signingIdentity"` dans `apps/desktop/src-tauri/tauri.conf.json` → **les
  prochains `cargo tauri build` produiront une app SIGNÉE** (au lieu d'ad-hoc).
- **🔴 RESTE À FAIRE (ton feu vert)** — la **notarisation** (soumission à Apple, sinon Gatekeeper bloque encore
  sur les autres Mac) :
  1. `cargo tauri build` (produit Memoria.app signé).
  2. Notariser via le profil trousseau (réf mémoire `PrimoStudio-Notary` / `Primask`) :
     `xcrun notarytool submit <chemin>.dmg --keychain-profile "PrimoStudio-Notary" --wait`
  3. `xcrun stapler staple Memoria.app` (agrafe le ticket) → app installable partout sans avertissement.
  - Alternative : Tauri v2 notarise au build si `APPLE_KEYCHAIN_PROFILE` (ou `APPLE_ID`/`APPLE_PASSWORD`/
    `APPLE_TEAM_ID`) sont dans l'environnement.

### Pourquoi c'est important
La publication npm + la signature/notarisation sont **la condition pour installer Memoria proprement chez
un tiers** (ton ami) : aujourd'hui tout passe par des chemins locaux et une app non signée. Une fois ces 2
verrous levés, `npx @<scope>/cli` et un `Memoria.app` notarisé suffisent.
